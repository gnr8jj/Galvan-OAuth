i. What happens when a user accesses /profile without logging in?
When a user attempts to access /profile, the server returns the message "Unauthorized: Please login first." This is handled by checking if the user is logged in and if not, access is denied and the user is blocked from viewing the profile data.

ii. What data is returned after successful login?
After a successful login, it returns a JSON object containing the user's profile information, including their username (login), display name, avatar URL, email address, public repository count, follower and following counts, profile URL, and location. This data is stored in the session and displayed on the /profile page.

iii. Why is OAuth considered more secure than traditional login?
OAuth is more secure because the application never handles or stores the password. Instead, it is handled by GitHub, which issues a temporary token.

v. What did you learn from this activity?
How OAuth 2.0 works in practice and how user authentication can be securely handed over to a third-party provider without exposing credentials. It also showed us the importance of correctly configuring URLs and checking API routes.
